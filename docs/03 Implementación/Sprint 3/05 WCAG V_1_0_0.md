# Evaluación de Accesibilidad Web (WCAG)

**Nombre del Proyecto:** PathSeek

**Nivel de Conformidad Objetivo:** WCAG 2.2 Nivel AA; documentación previa: WCAG 2.1 AA.

**Herramientas Utilizadas:** lectura de fuentes Flutter/HTML y documentación; cálculo sRGB de contraste con PowerShell; inventario de navegador mediante control de aplicaciones. **Lighthouse, axe DevTools, WAVE y lector de pantalla: no ejecutados.**

**Fecha / versión:** 2026-10-27 / V_1_0_0. **Rama:** `feature/sprint03-qa`.

La [consigna](evidencias/00%20Consigna%20y%20r%C3%BAbrica%20recibidas.md) permite 2.1/2.2 AA; esta evaluación adopta 2.2 como objetivo de cierre. El [estándar W3C](https://www.w3.org/TR/WCAG22/) añade criterios de foco, arrastre, tamaño de objetivo y autenticación, entre otros. Las declaraciones previas 2.1 no prueban 2.2. Conformidad requiere evaluar páginas y procesos completos, no obtener una puntuación automática aislada.

## 1. Resumen de Accesibilidad por Principios

| Principio | Observaciones sustentadas | Estado / porcentaje |
| --- | --- | --- |
| Perceptible | Cinco pares de colores superan 4,5:1 en cálculo estático; existen etiquetas y texto alternativo semántico en fuentes | Evaluación parcial; porcentaje no calculado. Sin inspección renderizada completa. |
| Operable | Login define FocusNode y envío al siguiente campo; tema define mínimos de 48×48 para algunos botones | Evaluación parcial de código; Tab/Shift+Tab y objetivos reales sin comprobar. |
| Comprensible | Correo/contraseña tienen etiquetas, autofill y validadores; error de login usa liveRegion | Evidencia de diseño; anuncio, recuperación de error y autenticación accesible pendientes en navegador. |
| Robusto | Existen Semantics y tooltips en Flutter; HTML fuente no declara lang | Riesgo de idioma y semántica a comprobar; árbol accesible renderizado no inspeccionado. |

No se informa porcentaje de conformidad ni puntuación Lighthouse: no existe ejecución que los sustente.

### Alcance y acceso

| Pantalla/componente | Tipo de revisión realizada | Lo que no se realizó |
| --- | --- | --- |
| Login | Lectura de login_page.dart: etiquetas, foco, autofill, tooltip y región de error | Navegación real, anuncio por lector, pegado y gestor de contraseñas. |
| Mapa/detalle de ruta | Lectura de interactive_route_map.dart: controles, selector y etiquetas semánticas | Teclado completo, alternativa al arrastre, lectura de marcadores y anuncios reales. |
| Tema compartido | Lectura de app_theme.dart y cálculo de cinco contrastes | Estados hover/focus/disabled, overlays y todos los pares reales. |
| Documento HTML | Lectura de frontend/web/index.html | DOM final tras Flutter y semántica habilitada. |
| Dashboard, formularios, clientes, avisos, reportes y compensación | Antecedentes de pruebas/diseño | Sin auditoría dinámica por pantalla en esta etapa. |

El inventario mostró navegadores disponibles; la captura/control de Edge se detuvo porque la herramienta no pudo identificar con suficiente confianza la URL activa en Windows. Se detuvo la interacción. Esto es una limitación del entorno, **no un fallo WCAG de PathSeek**. No se construyó/levantó Flutter ni se alteró configuración para eludirla.

### Mediciones directas de contraste

Fuente: [app_theme.dart](../../../frontend/lib/core/theme/app_theme.dart). Método: convertir cada canal sRGB a luminancia lineal; luminancia relativa `L = 0,2126R + 0,7152G + 0,0722B`; contraste `(Lmayor + 0,05)/(Lmenor + 0,05)`. Valores opacos del código, sin muestreo de pantalla.

| Par | Colores | Ratio calculado | Interpretación limitada |
| --- | --- | ---: | --- |
| textHighContrast / blanco | #191C19 / #FFFFFF | 17,19:1 | Supera mínimo de texto normal para este par. |
| mutedText / blanco | #47564C / #FFFFFF | 7,77:1 | Supera mínimo para este par. |
| primary / blanco | #1B6D29 / #FFFFFF | 6,43:1 | Supera mínimo para este par. |
| blanco / primaryDark | #FFFFFF / #0D4715 | 10,89:1 | Supera mínimo para este par. |
| danger / dangerSurface | #8C2820 / #FFE9E7 | 7,40:1 | Supera mínimo para el error de login leído en fuentes. |

Estos ratios coinciden parcialmente con el [antecedente UI/UX](../Sprint%203/08%20Redise%C3%B1o%20integral%20UIUX%20Pro%20Max%20V_1_0_0.md); los valores anteriores son históricos y estos cinco se recalcularon ahora. No se extrapola conformidad a todos los controles, imágenes, estados ni páginas.

## 2. Hallazgos Principales y Correcciones

No se aplicaron correcciones de código en esta etapa. Los ejemplos académicos de alt/contraste/Tab no se convierten en defectos reales sin reproducción.

| Criterio de conformidad | Problema detectado o evidencia real | Componente afectado | Solución aplicada / acción recomendada |
| --- | --- | --- | --- |
| 1.1.1 Contenido no textual | Marcadores/controles usan Semantics/Tooltip; no se verificó su representación accesible | Mapa de ruta | Ninguna corrección aplicada; auditar árbol semántico y alternativa textual de toda la ruta. |
| 1.3.1 Información y relaciones; 4.1.2 Nombre, función, valor | Login usa encabezado semántico, labelText y tooltip de visibilidad | Login | Controles existentes en fuentes; verificar con lector de pantalla, sin declararlos aprobados por ejecución. |
| 1.4.3 Contraste mínimo | Cinco pares opacos medidos por encima del mínimo; sin fallo confirmado de esos pares | Tema/login | Ninguna corrección necesaria demostrada; medir estados y pares restantes en renderizado. |
| 1.4.10 Reflow; 1.4.4 Cambio de tamaño | Historial refiere regresiones hasta escala de texto 2 y varios viewports | Shell, formularios y catálogos | Sin nueva corrección; probar zoom 200 %/400 %, 320 CSS px y ausencia de pérdida de contenido. |
| 2.1.1 Teclado; 2.1.2 Sin trampas | Código mueve foco correo → contraseña; no hay recorrido real completo | Login y navegación | Sin corrección nueva; registrar Tab/Shift+Tab/Enter/Escape por pantalla y modal. |
| 2.4.3 Orden del foco; 2.4.7 Foco visible; 2.4.11 Foco no oculto | Orden y visibilidad final no observados; bordes focused definidos en tema | Shell, login, diálogos | Pendiente: captura del foco y comprobación con menús/banners abiertos. |
| 2.5.7 Movimientos de arrastre; 2.5.8 Tamaño del objetivo | Mapa tiene selector/zoom; tema establece mínimo 48×48 en algunos controles | Mapa y botones | No se midieron cajas finales ni toda operación alternativa; revisar todos los controles, excepciones y espaciado. |
| 3.1.1 Idioma de la página | Etiqueta html del archivo fuente sin atributo lang | frontend/web/index.html | Riesgo confirmado en fuente, fallo final por verificar en DOM servido. Proponer lang apropiado en una etapa de código autorizada. |
| 3.3.1 Errores; 3.3.2 Etiquetas; 4.1.3 Mensajes de estado | Validadores/labelText y error con liveRegion están presentes | Login | Verificar anuncios y asociación error-campo. No simular resultado de lector. |
| 3.3.8 Autenticación accesible | Autofill de usuario/contraseña y ausencia de bloqueo explícito de pegado observados | Login | Probar pegado, gestor y recuperación de sesión; no inferir cumplimiento solo de autofillHints. |

### Evidencia exacta necesaria para cerrar

Se requiere una URL accesible del build identificado, fecha/versión de navegador, revisión Git/estado del árbol y acceso a sesiones de prueba por rol mediante un canal local seguro. No enviar contraseñas ni tokens en este documento ni en mensajes.

| Pantallas / rol | Evidencia solicitada | Verificación manual complementaria |
| --- | --- | --- |
| Login, error y sesión expirada | axe JSON y Lighthouse HTML/JSON, versión y viewport | Pegado/autofill, foco, anuncio de error y recuperación. |
| Dashboard y shell de ADMIN/OPERADOR/AUDITOR | Informes por pantalla, con semántica Flutter activa | Tab completo, navegación, foco no oculto y permisos visuales. |
| Flota/conductores/pedidos/clientes y formularios | Informes en vacío, datos, errores y diálogo | Etiquetas, orden del foco, mensajes y zoom/reflow. |
| Rutas, detalle, mapa y selector de ubicación | Informe del DOM y captura de árbol accesible | Alternativa al mapa/arrastre, teclado y descripción de secuencia. |
| Conductor: avisos, ejecución y offline | Informe con banner/avisos y grabación saneada | Lectura de estados, sincronización y foco ante cambios. |
| Reportes y compensación | Informes de las páginas | Filtros, descarga y anuncios. PDF requiere evaluación de accesibilidad propia, no inferida del HTML. |

Para cada captura indicar pasos, resultado esperado/obtenido, criterio, severidad y responsable; saneamiento de datos personales y sesión antes de compartir. Un resultado axe de cero alertas sin árbol semántico inspeccionado puede omitir gran parte de una interfaz CanvasKit; no equivale a accesibilidad total.

La evidencia pendiente puede entregarse como informes exportados y grabación/capturas de teclado/lector. El documento conserva evaluación útil de fuentes y mediciones, pero EN-006 y la conformidad AA completa permanecen pendientes.
