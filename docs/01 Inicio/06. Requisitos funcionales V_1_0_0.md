## 1. Marco de Elicitación Holística y Ética

### 1.1 Enfoque de recolección de necesidades

La elicitation de requisitos para PathSeek considera:

- **Grupos de usuarios diversos:** Administradores logísticos, conductores con distintos niveles de formación, clientes con necesidades variables y personal académico supervisor.
- **Contexto local (glocal):** Las condiciones operativas de Huancayo (congestión vehicular, infraestructura vial, direcciones sin nomenclatura estándar, restricciones vehiculares por placa, clima con neblina) determinan requisitos específicos que no existen en soluciones genéricas de optimización de rutas.
- **Perspectiva ética:** Protección de datos personales (Ley N.° 29733), consentimiento informado para datos de conductores, acceso equitativo a la información y accesibilidad para usuarios con distintos niveles de alfabetización tecnológica.

### 1.2 Técnicas de elicitation aplicadas

| Técnica | Participantes | Resultado |
| ------- | ------------- | --------- |
| Análisis de documentación existente | Equipo del proyecto | Requerimientos de la consigna, normativa, estándares |
| Entrevistas a usuarios potenciales | Conductores, personal operativo | Necesidades de modo conductor, puntos de referencia, restricciones reales |
| Análisis de datos operativos | UGEL Huancayo | Volumen de entregas, flota, costos, tiempos |
| Benchmarking tecnológico | Equipo del proyecto | Alternativas de stack, APIs de mapas, metaheurísticas |
| Revisión de estándares | Equipo del proyecto | ISO/IEC 25010, OWASP, WCAG 2.1, ISO 14083 |

## 2. Catálogo de Requisitos Funcionales

### RF-001: Gestión de Flota

- **Descripción Atómica:** El sistema debe permitir el registro y gestión de vehículos con placa, tipo (camioneta, furgón, moto), capacidad de carga (kg), consumo de combustible (km/L), factor de emisión de CO₂ (kg CO₂/km) y año de fabricación.
- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que el administrador tiene permisos de gestión de flota

CUANDO registra un vehículo con datos completos y válidos

ENTONCES el sistema almacena el vehículo y lo muestra en la lista de flota

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que el administrador edita los datos de un vehículo registrado

CUANDO modifica capacidad, consumo o factor de emisión

ENTONCES el sistema actualiza el registro y refleja los cambios en el dashboard

DADO que el administrador intenta registrar un vehículo con placa duplicada

ENTONCES el sistema deniega la acción y muestra un mensaje indicando que la placa ya existe

---

### RF-002: Gestión de Pedidos

- **Descripción Atómica:** El sistema debe permitir el registro de pedidos con ID de cliente, dirección de entrega, coordenadas GPS, peso (kg), volumen (m³), ventana de tiempo (hora inicio-fin), prioridad (express, estándar, económico) y tipo de producto (perecedero, no perecedero).
- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que el operador tiene permisos de registro de pedidos

CUANDO registra un pedido con dirección, coordenadas, peso, volumen y ventana de tiempo válidos

ENTONCES el sistema almacena el pedido y lo incluye en la cola de planificación

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que el operador registra un pedido con punto de referencia en lugar de dirección formal

CUANDO ingresa texto libre como "frente a la bodega El Ahorro"

ENTONCES el sistema acepta el punto de referencia y lo asocia al pedido

DADO que el operador registra un pedido con ventana de tiempo incompatible (hora fin anterior a hora inicio)

ENTONCES el sistema deniega la acción y muestra error de validación

---

### RF-003: Generación de Rutas Optimizadas

- **Descripción Atómica:** El sistema debe calcular rutas óptimas mediante una metaheurística (GA, SA, ACO o Tabú) considerando distancia total, tiempo total, consumo de combustible, emisiones de CO₂, penalizaciones por entregas tardías y descanso obligatorio de conductores.
- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que existen pedidos registrados y vehículos disponibles con sus ventanas de tiempo

CUANDO el operador solicita la generación de rutas

ENTONCES el sistema retorna rutas óptimas en ≤ 45 segundos para 150 pedidos y 15 vehículos

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que un conductor tiene restricción vehicular por último dígito de placa (DS N.° 033-2012-MTC)

CUANDO el sistema genera rutas para ese día

ENTONCES excluye al vehículo restringido de la asignación

DADO que la ventana de tiempo de una entrega es inalcanzable con la capacidad disponible

ENTONCES el sistema marca la entrega como pendiente y sugiere reprogramación

---

### RF-004: Visualización de Rutas en Mapa

- **Descripción Atómica:** El sistema debe mostrar las rutas optimizadas en un mapa interactivo (Leaflet/OpenStreetMap) con trazado de ruta, puntos de entrega, tiempo estimado por tramo y nivel de congestión del tráfico (verde/amarillo/rojo).
- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que existen rutas generadas por el algoritmo de optimización

CUANDO el operador abre la vista de mapa

ENTONCES el sistema muestra el trazado de cada ruta con colores diferenciados, puntos de entrega y tiempos estimados por tramo

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que un tramo tiene congestión alta según datos de tráfico

CUANDO el operador visualiza la ruta

ENTONCES el tramo aparece en rojo con indicador de congestión

DADO que el operador selecciona un punto de entrega en el mapa

ENTONCES el sistema muestra detalles del pedido (cliente, ventana de tiempo, peso)

---

### RF-005: Dashboard de Indicadores

- **Descripción Atómica:** El sistema debe mostrar métricas en tiempo real: distancia recorrida total (km), emisiones de CO₂ (kg), combustible ahorrado (L), cumplimiento de ventanas de tiempo (%), ahorro comparado con ruta secuencial (%) y equivalente ambiental.
- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que existen rutas completadas en el sistema

CUANDO el operador accede al dashboard

ENTONCES el sistema muestra métricas actualizadas con datos de las últimas rutas ejecutadas

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que se completaron entregas con ahorro significativo

CUANDO el operador consulta el dashboard

ENTONCES el sistema muestra equivalente ambiental ("Has ahorrado S/ XX en combustible hoy")

DADO que no hay datos de rutas completadas

ENTONCES el sistema muestra el dashboard vacío con mensaje orientador

---

### RF-006: Reportes de Sostenibilidad

- **Descripción Atómica:** El sistema debe generar reportes descargables (PDF) con resumen de emisiones de CO₂ por ruta, costo del ciclo de vida de la flota (combustible + mantenimiento + depreciación + seguros), ahorro en créditos de carbono y cumplimiento de metas de cero carbono neto.
- **Prioridad:** Media

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que existen datos de rutas ejecutadas y costos de la flota

CUANDO el operador solicita la generación de un reporte de sostenibilidad

ENTONCES el sistema genera un PDF descargable con métricas de emisiones, costos y ahorro

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que el operador selecciona un rango de fechas específico

CUANDO genera el reporte

ENTONCES el sistema filtra los datos por el rango seleccionado

DADO que el operador genera un reporte anual

ENTONCES el sistema incluye el plan de compensación de carbono y树木 equivalentes

---

### RF-007: Re-optimización Dinámica

- **Descripción Atómica:** El sistema debe permitir re-calcular rutas ante nuevos pedidos, cancelaciones, accidentes de tránsito o averías de vehículos en ≤ 30 segundos.
- **Prioridad:** Alta

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que existen rutas activas en ejecución

CUANDO se produce un cambio (nuevo pedido, cancelación o incidente)

ENTONCES el sistema re-calcula las rutas afectadas en ≤ 30 segundos y notifica a los conductores

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que se produce un accidente en un tramo de una ruta activa

CUANDO el sistema recibe la alerta de incidente

ENTONCES re-planifica la ruta evitando el tramo afectado

DADO que se produce un cambio múltiple simultáneo (varios pedidos nuevos)

ENTONCES el sistema procesa todos los cambios y genera una nueva planificación coherente

---

### RF-008: Gestión de Conductores

- **Descripción Atómica:** El sistema debe permitir el registro de conductores con nombre, DNI, licencia de conducir (categoría), años de experiencia, disponibilidad horaria y número de contacto, considerando restricciones de la Ley N.° 30224 (jornadas máximas de 8 horas y descansos obligatorios).
- **Prioridad:** Media

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que el administrador tiene permisos de gestión de conductores

CUANDO registra un conductor con datos completos

ENTONCES el sistema almacena el conductor y lo incluye en la asignación de rutas

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que un conductor ya acumula 8 horas de conducción continua

CUANDO el sistema planifica rutas

ENTONCES excluye al conductor de nuevas asignaciones hasta completar el descanso obligatorio

DADO que un conductor reside en un distrito alejado (ej. Villa El Salvador)

ENTONCES el sistema considera su punto de partida al asignar rutas

---

### RF-009: Módulo de Clientes

- **Descripción Atómica:** El sistema debe permitir a los clientes registrar sus preferencias de entrega (horarios preferidos, puntos de referencia, restricciones de acceso).
- **Prioridad:** Baja

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que un cliente tiene acceso a la plataforma

CUANDO registra sus preferencias de entrega

ENTONCES el sistema almacena las preferencias y las aplica al generar rutas

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que un cliente indica horarios variables de atención (ej. bodega con horario 6:00 AM - 9:00 PM)

CUANDO registra las ventanas de tiempo

ENTONCES el sistema considera las ventanas al optimizar rutas

DADO que un cliente indica restricciones de acceso para su dirección

ENTONCES el sistema incorpora las restricciones en la planificación

---

### RF-010: Plan de Compensación de Carbono

- **Descripción Atómica:** El sistema debe calcular el CO₂ total emitido y proponer un plan de compensación, sugiriendo alianzas con proyectos locales de reforestación (ej. Lomas de Lima, Parque Zonal Huáscar).
- **Prioridad:** Baja

- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)

DADO que existen datos acumulados de emisiones de CO₂

CUANDO el administrador solicita el plan de compensación

ENTONCES el sistema calcula las emisiones anuales y sugiere proyectos de reforestación con树木 equivalentes

#### Ruta Feliz (Flujos Alternativos Válidos)

DADO que las emisiones anuales equivalen a 42 toneladas de CO₂

CUANDO el sistema genera el plan

ENTONCES sugiere participar en "Árboles para Lima" con aproximadamente 2,100 árboles necesarios

DADO que no hay proyectos de reforestación configurados

ENTONCES el sistema muestra el cálculo de emisiones sin sugerencias de compensación
