# Registro de supuestos y restricciones

Proyecto: PathSeek
Código del documento: DOC-004
Versión: V_1_0_0
Fecha: 2026-08-25

---

## 1. Propósito

El presente documento identifica y registra los **supuestos y restricciones** que condicionan la planificación, diseño, desarrollo, implementación y evaluación del proyecto **PathSeek**.

Los supuestos representan condiciones que se consideran válidas para la planificación del proyecto. Las restricciones representan condiciones, límites o reglas que deberán ser respetadas durante su ejecución.

---

## 5. Matriz de impacto de los supuestos

| ID | Si no se cumple | Acción de contingencia |
| ------ | ------------------------------------------------------------------ | ---------------------------------------------------- |
| ASU-01 | No se dispone del contexto operativo de UGEL Huancayo | Redefinir escenario de validación con datos sintéticos |
| ASU-02 | Las cifras de flota/entregas son diferentes | Ajustar datos de prueba y escenarios de carga |
| ASU-03 | El ámbito geográfico no es Huancayo | Modificar mapeo y restricciones geográficas |
| ASU-04 | No hay datos georreferenciados | Crear datos sintéticos o usar otras fuentes |
| ASU-05 | No hay datos de prueba suficientes | Generar datos sintéticos basados en el contexto |
| ASU-06 | No funciona OpenStreetMap | Utilizar Google Maps API o alternativa |
| ASU-07 | No hay fuente de tráfico disponible | Recurrir a datos simulados o carga manual |
| ASU-08 | Precisión de tráfico muy baja | Implementar validación y ponderación de fuentes |
| ASU-09 | No hay carga manual de tráfico | Diseñar interfaz de ingreso manual obligatorio |
| ASU-10 | No se logra implementar el algoritmo básico | Revisar alcance del MVP y simplificar requisitos |
| ASU-11 | El cronograma de 14 semanas no se cumple | Replanificar prioridades del MVP |
| ASU-12 | Las tecnologías propuestas no son viables | Evaluar alternativas equivalentes |
| ASU-13 | No hay herramientas de desarrollo | Gestionar adquisición o acceso alternativo |
| ASU-14 | La re-optimización no es viable | Revisar arquitectura y algoritmo |
| ASU-15 | Los estándares no son aplicables al MVP | Priorizar estándares críticos (OWASP, WCAG) |

## 6. Gestión de cambios

Cualquier modificación significativa de los supuestos o restricciones deberá:

1. Registrar la causa del cambio.
2. Identificar el supuesto o restricción afectada.
3. Evaluar impacto en alcance, cronograma, presupuesto, calidad y técnica.
4. Documentar la decisión adoptada.
5. Ser revisada antes de incorporarse al desarrollo.

---

## 7. Criterios de revisión

El registro deberá revisarse:

* Al inicio del proyecto.
* Al finalizar cada iteración.
* Cuando cambien los requerimientos.
* Cuando aparezcan nuevas restricciones técnicas.
* Cuando cambien las fuentes de datos.
* Antes de la validación final del MVP.
