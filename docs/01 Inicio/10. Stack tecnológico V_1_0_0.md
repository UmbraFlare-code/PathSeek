## 2. Alternativa Seleccionada

**Alternativa 2: Node/Express + Flutter + PostgreSQL**

### 2.1 Lista de Justificaciones

La selección de la combinación **Node.js (Express) + Flutter + PostgreSQL** se sustenta en las siguientes justificaciones:

1. **Frontend multi-plataforma (Flutter/Dart):** Flutter usa Dart, un lenguaje de tipado estático con hot reload y compilación nativa, que permite construir con una sola base de código la web del operador, el dashboard y el modo conductor móvil, acelerando el desarrollo del MVP en las 14 semanas.

2. **Express como backend único y maduro:** Express.js es el framework Node.js más consolidado, con ecosistema enorme de middleware, documentación abundante y soporte comunitario masivo, ideal para la API REST del sistema. Se usa como **único backend**, sin coexistir con FastAPI.

3. **Tipado estático en todo el stack:** El frontend Flutter usa **Dart** (lenguaje de tipado estático con null safety) y el backend Express se implementa en TypeScript, manteniendo calidad y mantenibilidad en toda la solución.

4. **Flutter como framework empresarial:** UI declarativa por widgets, gestión de estado con Provider/BLoC, navegación con Navigator/go_router, formularios con validación y clientes HTTP (http/dio); soporta la complejidad de un dashboard con mapas, tablas de indicadores y reportes.

5. **Escalabilidad (Node async I/O):** El modelo asíncrono y no bloqueante de Node.js maneja eficientemente múltiples peticiones concurrentes (dashboard en tiempo real, consultas de tráfico), cumpliendo el requisito de 1,000 pedidos diarios y 50 vehículos.

6. **Optimización con librerías de JS/TS:** Implementaciones de Algoritmos Genéticos, Búsqueda Tabú, Colonia de Hormigas y Enfriamiento Simulado en el ecosistema JavaScript/TypeScript permiten resolver VRPTW/Green VRP dentro del requisito de ≤ 45 segundos.

7. **Costo de infraestructura moderado-bajo:** Node.js tiene consumo eficiente de recursos, alineado con el presupuesto de S/ 500,000, el LCC a 3 años y los criterios de eco-diseño / Green Software.

8. **Restricciones de código abierto:** Express, Flutter y PostgreSQL son tecnologías de código abierto, cumpliendo la restricción RES-07 del proyecto.

9. **PostgreSQL:** Relacional, con soporte geográfico (PostGIS) para cálculos de rutas y coordenadas GPS, y capacidad de escalamiento horizontal.

10. **Reutilización de widgets:** Flutter permite construir widgets reutilizables (mapa, dashboard, formularios de pedidos) acelerando los RF-004, RF-005 y RF-010.

### 2.2 Componentes del stack

| Capa            | Tecnología              | Justificación                                                 |
| --------------- | ----------------------- | ------------------------------------------------------------- |
| Backend (único) | Node.js + Express       | framework maduro, async I/O, ecosistema de middleware         |
| Frontend        | Flutter (Dart)          | UI declarativa por widgets, hot reload, multi-plataforma (web + móvil) |
| Base de datos   | PostgreSQL              | relacional, soporte geográfico (PostGIS), 3FN                 |
| Mapas           | flutter_map + OpenStreetMap | código abierto, gratuito, cumplimiento RES-06                 |
| Caché           | Redis                   | sesiones y caché de consultas frecuentes                      |
| Autenticación   | JWT + OAuth2            | OWASP, integración con servicios externos                     |

**Alternativas descartadas:** MEAN con MongoDB (base de datos no relacional menos adecuada para integridad transaccional y rutas geográficas), Java Spring Boot (mayor consumo de memoria y curva de aprendizaje alta). **FastAPI no se considera:** el backend del proyecto es **únicamente Node.js/Express**.
