## 1. Alternativas de Stack Evaluadas

Se evalúan 3 alternativas de stack mediante criterios multidimensionales, alineados con los objetivos de escalabilidad, perfil del equipo y bajo consumo energético.

| Criterio | Alternativa 1: MEAN (Node/Express + Angular + MongoDB) | Alternativa 2: Node/Express + Angular + PostgreSQL | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
| -------- | ------------------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------ |
| Curva de Aprendizaje | Baja-Media (JavaScript unificado) | Baja-Media (JavaScript unificado) | Alta (Verboso, fuertemente tipado) |
| Costo de Infraestructura | Moderado (Node async I/O) | Moderado-Bajo (Node async I/O) | Alto (Mayor consumo memoria JVM) |
| Soporte Comunitario | Masivo / Muy Alto | Masivo / Muy Alto | Masivo / Corporativo consolidado |
| Eficiencia Energética / Eco-Design | Media | Media-Alta | Media-Baja (Warm-up JVM) |
| Idoneidad para Optimización | Media (cómputo matemático en JS) | Media-Alta (JS/TS con librerías) | Media (JVM, ecosistema robusto) |
| Madurez Empresarial | Alta (Angular) | **Alta (Angular + Express)** | Alta |
| Puntaje | 3.8 | **4.4** | 3.4 |

## 2. Alternativa Seleccionada

**Alternativa 2: Node/Express + Angular + PostgreSQL**

### 2.1 Lista de Justificaciones

La selección de la combinación **Node.js (Express) + Angular + PostgreSQL** se sustenta en las siguientes justificaciones:

1. **Lenguaje unificado (JavaScript/TypeScript):** Frontend y backend comparten el mismo lenguaje, reduciendo la curva de aprendizaje del equipo PIPRE y acelerando el desarrollo del MVP en las 14 semanas.

2. **Express como backend único y maduro:** Express.js es el framework Node.js más consolidado, con ecosistema enorme de middleware, documentación abundante y soporte comunitario masivo, ideal para la API REST del sistema. Se usa como **único backend**, sin coexistir con FastAPI.

3. **TypeScript de extremo a extremo:** Angular usa TypeScript por defecto; al usar Express con TypeScript se mantiene tipado estático en todo el stack, mejorando mantenibilidad y reduciendo errores.

4. **Angular como framework empresarial:** Arquitectura completa (componentes, servicios, inyección de dependencias, routing, formularios reactivos, HTTP client) que soporta la complejidad de un dashboard con mapas, tablas de indicadores y reportes.

5. **Escalabilidad (Node async I/O):** El modelo asíncrono y no bloqueante de Node.js maneja eficientemente múltiples peticiones concurrentes (dashboard en tiempo real, consultas de tráfico), cumpliendo el requisito de 1,000 pedidos diarios y 50 vehículos.

6. **Optimización con librerías de JS/TS:** Implementaciones de Algoritmos Genéticos, Búsqueda Tabú, Colonia de Hormigas y Enfriamiento Simulado en el ecosistema JavaScript/TypeScript permiten resolver VRPTW/Green VRP dentro del requisito de ≤ 45 segundos.

7. **Costo de infraestructura moderado-bajo:** Node.js tiene consumo eficiente de recursos, alineado con el presupuesto de S/ 500,000, el LCC a 3 años y los criterios de eco-diseño / Green Software.

8. **Restricciones de código abierto:** Express, Angular y PostgreSQL son tecnologías de código abierto, cumpliendo la restricción RES-07 del proyecto.

9. **PostgreSQL:** Relacional, con soporte geográfico (PostGIS) para cálculos de rutas y coordenadas GPS, y capacidad de escalamiento horizontal.

10. **Reutilización de componentes:** Angular permite construir componentes reutilizables (mapa, dashboard, formularios de pedidos) acelerando los RF-004, RF-005 y RF-010.

### 2.2 Componentes del stack

| Capa | Tecnología | Justificación |
| ---- | ---------- | ------------- |
| Backend (único) | Node.js + Express | framework maduro, async I/O, ecosistema de middleware |
| Frontend | Angular (TypeScript) | framework empresarial, componentes, inyección de dependencias |
| Base de datos | PostgreSQL | relacional, soporte geográfico (PostGIS), 3FN |
| Mapas | Leaflet + OpenStreetMap | código abierto, gratuito, cumplimiento RES-06 |
| Caché | Redis | sesiones y caché de consultas frecuentes |
| Autenticación | JWT + OAuth2 | OWASP, integración con servicios externos |

**Alternativas descartadas:** MEAN con MongoDB (base de datos no relacional menos adecuada para integridad transaccional y rutas geográficas), Java Spring Boot (mayor consumo de memoria y curva de aprendizaje alta). **FastAPI no se considera:** el backend del proyecto es **únicamente Node.js/Express**.
