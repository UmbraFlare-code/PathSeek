## 2. Propósito y justificación del proyecto

**UGEL Huancayo** es una institución educativa ubicada en Huancayo que realiza operaciones de distribución de última milla.

La operación presenta los siguientes problemas:

* Congestión vehicular en horas punta.
* Altos costos de combustible y mantenimiento.
* Emisiones aproximadas de **3.5 toneladas de CO₂ mensuales** por una flota de 15 camionetas.
* Incumplimiento de ventanas de tiempo en aproximadamente el **22 % de las entregas**.
* Necesidad de considerar restricciones de tránsito, seguridad vial, condiciones climáticas e infraestructura.

Estos problemas justifican el desarrollo de una plataforma web que optimice rutas considerando simultáneamente distancia, tiempo, consumo de combustible, emisiones de CO₂ y penalizaciones por incumplimiento de ventanas de tiempo.

## 3. Objetivos medibles (Criterios SMART)

### 3.1 Objetivo general

Desarrollar una plataforma web funcional para UGEL Huancayo que permita optimizar rutas de distribución de última milla reduciendo un **15 % la distancia recorrida** y un **10 % las emisiones de CO₂** respecto de una planificación secuencial, en un plazo de **14 semanas** con un presupuesto máximo de **S/ 500,000**.

### 3.2 Objetivos específicos

| ID | Objetivo | Específico | Medible | Alcanzable | Relevante | Temporal |
| ---- | ----------------------------------------------------------- | ---------- | --------------------------- | ----------- | -------------------------- | -------------- |
| O-01 | Registrar y gestionar flota, pedidos y conductores | Sí | CRUD completo de entidades | Sí | Base para optimización | Semanas 4–7 |
| O-02 | Generar rutas optimizadas mediante metaheurística | Sí | Solución válida en ≤ 45 s para 150 pedidos/15 vehículos | Sí | Función principal | Semanas 4–11 |
| O-03 | Visualizar rutas en mapa interactivo | Sí | Mapa con trazado, puntos y tiempos | Sí | Interface de usuario | Semanas 8–11 |

## 4. Requisitos de alto nivel

### 4.1 Requerimientos funcionales principales

| ID | Requerimiento | Descripción |
| ------ | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| RF-01 | Gestión de flota | Registro de vehículos con placa, tipo, capacidad, consumo, emisión de CO₂ y año de fabricación |
| RF-02 | Gestión de pedidos | Registro con dirección, coordenadas GPS, peso, volumen, ventana de tiempo, prioridad y tipo de producto |
| RF-03 | Gestión de conductores | Registro con nombre, DNI, licencia, categoría, experiencia, disponibilidad horaria y contacto |
| RF-04 | Generación de rutas | Algoritmo que optimice distancia, tiempo, consumo, emisiones y penalizaciones por entregas tardías |
| RF-05 | Visualización en mapas | Trazado de ruta, puntos de entrega, tiempo estimado por tramo y nivel de congestión |
| RF-06 | Dashboard de indicadores | Distancia recorrida, emisiones, combustible ahorrado, cumplimiento de ventanas y ahorro vs. ruta secuencial |
| RF-07 | Re-optimización dinámica | Actualización de rutas ante nuevos pedidos, cancelaciones, accidentes o averías en ≤ 30 s |
| RF-08 | Modo conductor | Interfaz simplificada con ruta asignada, entregas pendientes y alertas de tráfico |
| RF-09 | Reportes PDF | Emisiones por ruta, costo del ciclo de vida, ahorro en créditos de carbono y cumplimiento de metas |
| RF-10 | Compensación de carbono | Plan orientado a carbono neutral en 3 años mediante optimización, migración y reforestación |

### 4.2 Requerimientos no funcionales principales

| ID | Requerimiento | Criterio de aceptación |
| ------ | --------------------------- | ---------------------------------------------------------------------------------------------- |
| RNF-01 | Rendimiento del algoritmo | Solución válida en ≤ 45 s para 150 pedidos y 15 vehículos |
| RNF-02 | Rendimiento de re-optimización | Re-optimización en ≤ 30 s ante cambios repentinos |
| RNF-03 | Escalabilidad | Soporte hasta 1,000 pedidos diarios y 50 vehículos |
| RNF-04 | Disponibilidad | 99.5 % durante horario operativo de 5:00 AM a 10:00 PM |
| RNF-05 | Seguridad | OWASP Top 10 + Ley N.° 29733 |
| RNF-06 | Accesibilidad | WCAG 2.1 nivel AA |
| RNF-07 | Conectividad | Funcionamiento en conexiones de baja velocidad |

### 4.3 Restricciones iniciales

* Presupuesto de desarrollo: **S/ 500,000**.
* Costo operativo anual: **S/ 120,000**.
* Tecnologías de código abierto (Python, FastAPI, React.js, PostgreSQL, Leaflet).
* Cumplimiento con Ley N.° 29733 y Ley N.° 30224.
* ISO/IEC 25010, OWASP Top 10, WCAG 2.1, ISO 14083.
